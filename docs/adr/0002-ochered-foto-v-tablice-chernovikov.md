# Очередь разбора фото — сама таблица черновиков приёма, без pg-boss

`docs/architecture.md` предполагал очереди на pg-boss. Для фото еды решили иначе: очередью служит таблица черновиков приёма. У черновика и так есть состояние, счётчик попыток и время следующей попытки, которые видит человек; pg-boss завёл бы вторую копию того же состояния, и её пришлось бы держать в согласии с черновиком. Воркер забирает черновики запросом `for update skip locked`, поэтому несколько воркеров не возьмут один черновик дважды. Каждый модуль сам обрабатывает свои задания через `AppModule.work`, ядро воркера только вызывает модули по кругу.

## Consequences

- Повторы, паузы между попытками и восстановление после падения воркера (черновик, застрявший в «разбирается», снова берётся в работу) реализованы в модуле еды, а не в библиотеке.
- **Исключение из «файлы — во внешнем хранилище» (`docs/architecture.md`).** Фото черновика лежит в самой строке `food_drafts` и удаляется при подтверждении или удалении черновика. Снимок временный, а внешнего хранилища пока нет; когда оно появится, перенести фото туда, оставив в строке ключ.
- Для этапа 2 (сканы PDF, вопросы с вариантами) вопрос открыт: если заданий без своей сущности станет много, общая очередь вроде pg-boss снова станет кандидатом.
